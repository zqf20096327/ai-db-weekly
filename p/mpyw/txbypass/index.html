🧭 简介解读层（AI·证据行可回查）

Go 静态分析 linter，报告在事务内误用其来源数据库句柄的代码

综述（解读层）

txbypass 是一个 Go linter，通过静态分析识别在事务回调中使用了外层数据库句柄（如 r.db 而非 tx）的代码——这类写入游离于事务之外，回滚后仍会留存。支持 database/sql、gorm、pgx、bun、ent、MongoDB 等库，可自动读取项目内自定义事务辅助函数。适用于使用这些库编写事务代码的 Go 项目。限制：单连接上的事务、savepoint 及部分回调模式不在读取范围。

  • 提供 outer-handle 与 outer-context 两条规则，可通过命令行标志或 golangci-lint 配置启停
  • 支持 database/sql、sqlx、pgx v4/v5、gorm、bun、ent、go-redis、MongoDB 等 20 余个库的事务 API
  • 可自动识别项目内自定义的事务辅助函数（invoker/begin），并支持通过 //txbypass:ignore 与 //txbypass:invokes 指令控制

适用场景（解读层）

  • CI 或 go vet / golangci-lint 流程中检测事务内误用外层连接句柄的代码
  • 使用多种 Go 数据库库且需要统一事务规范的代码库审查
  • 识别回滚后仍写入、锁等待、读不到未提交数据等游离于事务之外的操作
