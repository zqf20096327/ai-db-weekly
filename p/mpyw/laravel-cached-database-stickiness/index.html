Laravel 数据库粘性包：基于缓存在同一用户的连续请求间保持读写连接粘性

综述（解读层）

这是一个 Laravel 扩展包，通过缓存机制让同一用户在最近数秒内的连续请求保持数据库主从读写粘性状态，解决读写分离下主从延迟导致的数据不一致问题。适用于采用数据库主从读写分离架构的 Laravel 应用。要求 PHP 8.2+、Laravel 11-13，默认需手动在 config/app.php 注册 ConnectionServiceProvider（不支持包自动发现），缓存驱动推荐 redis 或 memcached，默认粘性 TTL 为 5 秒，可自定义解析器与队列 worker 行为。

  • 支持在 HTTP 请求间传递数据库粘性状态，队列 worker 默认读主库，可通过 ShouldAssumeFresh 等接口改读从库
  • 粘性判定源可替换：默认基于远程 IP，可切换为基于认证用户 ID 的解析器（需注册中间件）
  • 粘性 TTL 默认 5 秒，可通过 config/database.php 的 stickiness_ttl 配置项调整

适用场景（解读层）

  • 读写分离架构下，用户写入后立即读取需读到最新数据的场景
  • 基于认证用户而非 IP 判定粘性来源的多用户应用
  • 需要精确控制队列任务读主库或从库的队列消费场景
