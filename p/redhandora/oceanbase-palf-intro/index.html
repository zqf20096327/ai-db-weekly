把 Paxos 藏进文件式日志接口的 WAL 层，OceanBase 4.0 的复制日志系统

综述（解读层）

PALF 是 OceanBase 4.0 底层的复制 WAL 组件，发表于 PVLDB 2024，源码位于开源仓库 logservice/palf。它不做复制状态机重放，而是提供 append/read/trim 等文件式接口，把共识协议隐藏在接口之后，并补足可控选主、显式复制结果、CSN 跨组定序和镜像组同步四项能力。适合研究分布式数据库日志层设计、阅读 OceanBase 源码或部署物理备库的工程与研究人员。

  • 对外暴露 append、read、trim、mirror 等文件式接口，append 走异步回调 AppendCb，每条日志至多回显一次 success/failure
  • 基于选举优先级与 log reconfirmation 的可控选主，用 pending follower 角色兑现显式复制结果；CSN 随日志持久化，维持与 LSN 一致的单调关系，支持 follower read
  • 提供可独立重配置的镜像组（PALF group mirror）用于物理备库与归档恢复，配合 log barrier 与 config version 约束；写路径包含流水线复制、自适应分组复制与无锁 LSN 分配

适用场景（解读层）

  • 阅读 PVLDB 2024 论文的配套实现，研究把共识协议嵌入 WAL 模型的日志系统设计
  • 基于 OceanBase 开源仓库 logservice/palf 的源码阅读与二次开发
  • 搭建物理备库容灾、归档日志重放恢复等基于日志同步的下游服务
📖 README 首段存档原文 · 程序抽取

把共识协议接进数据库，通常的做法是复制状态机（RSM）：数据库是状态机，日志是命令流，每个副本重放命令流把自己推到同一个状态。PALF 反过来做——事务引擎用一套 append-only 的文件式接口写日志，共识协议藏在这套接口背后，对数据库不可见。
