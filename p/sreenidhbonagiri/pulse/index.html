基于 Go 与 SQS 的分布式网站/API 可用性监控平台

综述（解读层）

Pulse 对网站和 API 进行周期性 HTTP 检查，记录可用性与延迟，并在连续 3 次失败后创建事件、连续 2 次成功后解除。后端拆分为 API、调度器与 worker 三个 Go 服务，通过共享队列抽象支持 RabbitMQ（本地）与 Amazon SQS（AWS），重试借助延迟消息实现，并以 job_id 幂等去重。适合需要自托管监控并部署于 AWS 的开发者。

  • 调度器将检查任务发布到队列，worker 消费并执行 HTTP 请求、测量延迟、写入结果，任务处理具备幂等性与死信队列支持
  • 提供 REST API 管理监控项、手动触发检查、查看历史结果、事件与统计（可用率、平均延迟、延迟分位数等）
  • 每个 Go 进程暴露 Prometheus 指标，配套 Grafana 面板；AWS 基础设施由 Terraform 管理，CI/CD 使用 GitHub Actions 与 OIDC 免长期密钥部署

适用场景（解读层）

  • 持续监控多个网站与 API 端点的可用性和响应延迟
  • 需要分布式任务队列、重试与死信队列机制的自托管监控部署
  • 在 AWS 上通过 Terraform 和 GitHub Actions 构建 ECS Fargate + RDS + SQS 的参考部署
