🧭 简介解读层（AI·证据行可回查）

基于数据库表的 Django Tasks 后端，用 worker 进程执行任务，无需外部消息队列。

综述（解读层）

django-ox 将 Django Tasks 框架的任务队列实现为数据库中的表，支持 PostgreSQL、MySQL 8+ 和 SQLite，供已使用数据库的 Django 项目后台执行任务。worker 用 SKIP LOCKED 或原子更新抢占任务，附带 reaper 回收死 worker 的任务。执行语义为 at-least-once，任务需可安全重复执行。

  • 提供事务性入队：在 atomic() 内的 enqueue 随事务提交或回滚，无需 on_commit()
  • worker 死亡时由 reaper 按任务的重试预算将未完成任务归还队列，失败任务按指数退避重试并保留每次 traceback
  • 支持定期调度（admin 或 settings 中声明，无需独立 scheduler 进程）、ox_health 健康检查、ox_prune 清理及 /ox/metrics 监控

适用场景（解读层）

  • 已运行数据库且不想额外部署 Redis/RabbitMQ 的 Django 项目后台任务
  • 需要任务与应用数据在同一事务中一致提交或回滚的写入场景
  • 需通过 Django admin 查看重试、管理队列和定期调度的团队
📖 README 首段存档原文 · 程序抽取

Stop running Redis to send an email. django-ox runs Django's Tasks framework in your existing database. When a worker dies, another worker picks up its tasks. You run one process: the worker.
