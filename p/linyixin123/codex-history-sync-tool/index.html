面向 Windows 的 Codex Desktop 本地对话历史修复工具

综述（解读层）

该工具用于修复切换 API Key、provider、登录方式或 model_provider 后 Codex Desktop 本地历史列表不显示的问题。它读取 config.toml 识别当前配置，分析 state_5.sqlite 中 threads 的 provider 分布，将旧 provider 的线程同步到当前 provider，并自动创建 SQLite 备份以支持回滚。适用于确认本地数据库仍在、仅历史不显示的 Windows 用户；不支持跨设备迁移或数据库已损坏的情况。

  • 读取 config.toml 识别当前 model_provider，统计 threads 表中各 provider 的线程分布
  • 同步前通过 SQLite 原生 backup 流程自动创建备份，支持从最新或指定备份恢复
  • 提供 WinForms 图形界面与命令行两种方式，CLI 支持 status/sync/backup/restore 子命令并输出 JSON

适用场景（解读层）

  • 切换 API Key、provider 或登录方式后，本地历史仍在 ~/.codex 但 UI 列表为空的恢复
  • 同步前查看当前 provider 与历史线程分布，再决定是否执行修复
  • 通过备份机制在同步结果不符预期时回滚本地数据库
