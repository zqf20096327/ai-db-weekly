MySQL 备份守护进程，结合 XtraBackup 与二进制日志实现 PITR

综述（解读层）

MyHoard 是一个用于创建、管理和恢复 MySQL 备份的守护进程，备份存储于云对象存储（S3、GCS、Azure），内部调用 Percona XtraBackup 生成全量及增量备份，并近实时上传二进制日志。恢复时通过 relay log 索引分批回放日志实现时间点恢复（PITR）。它面向使用单主多从 GTID 架构的 Linux/systemd 环境，需要 MySQL 8.x+、ROW 格式二进制日志和 InnoDB 引擎，并通过 HTTP API 切换 active/restore/promote 模式以处理主库故障转移。

  • 支持定时全量备份、增量备份与近实时二进制日志备份，并提供基于时间戳的时间点恢复（PITR）
  • 备份加密与压缩后存储到 AWS S3、Google Cloud Storage 或 Azure 对象存储，恢复时通过 relay log 索引分批应用二进制日志
  • 提供 HTTP API 进行状态切换（active/restore/promote）、基于 statsd 的指标上报、Sentry 异常报告及按数量/年龄自动清理备份历史

适用场景（解读层）

  • 多节点 MySQL 部署中主库频繁切换（滚动升级或故障）时维持连续的备份事务流
  • 需要恢复到指定时间点以减小数据丢失窗口的场景
  • 本地磁盘空间有限、无法在恢复时容纳全部二进制日志的环境
📖 README 首段存档原文 · 程序抽取

MyHoard is a daemon for creating, managing and restoring MySQL backups. The backup data can be stored in any of the supported cloud object storages. It is functionally similar to pghoard
