MySQL 备份与 PITR 守护进程，基于 XtraBackup 和云对象存储

综述（解读层）

MyHoard 是一个用于创建、管理和恢复 MySQL 备份的守护进程，面向多节点主备环境。内部调用 Percona XtraBackup 执行全量和增量备份，近实时上传二进制日志，恢复时通过 relay log 索引分批回放 binlog，实现时间点恢复且本地磁盘占用少。仅支持 Linux，需 MySQL 8.x+、ROW 格式 binlog、GTID 及 InnoDB。

  • 支持周期性全量/增量备份与近实时二进制日志备份，存储于 AWS S3、Google Cloud Storage、Azure 等对象存储
  • 通过将备份 binlog 以 relay log 方式分批由 SQL 线程回放，实现时间点恢复（PITR）
  • 提供 HTTP API 进行模式切换与状态上报，支持 statsd 指标、Sentry 异常报告及基于数量/年龄的备份自动清理

适用场景（解读层）

  • 主节点可能频繁切换的多节点 MySQL 环境中维护连续的备份事务流
  • 需要将新服务器从对象存储恢复到指定时间点的场景
  • 希望以守护进程方式自动调度备份和 binlog 上传、并通过 HTTP API 控制备份/提升流程的运维环境

MyHoard is a daemon for creating, managing and restoring MySQL backups. The backup data can be stored in any of the supported cloud object storages. It is functionally similar to pghoard
