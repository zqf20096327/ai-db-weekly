读取 TiCDC Debezium 协议 Kafka 输出的 TiDB 变更捕获连接器

综述（解读层）

这是 Debezium 生态中处于孵化阶段的 TiDB 连接器，属于 DBZ-6269 第一阶段。它不复用 TiKV EventFeed，而是消费 TiCDC changefeed 以 protocol=debezium 模式写入 Kafka 的消息，在其上实现连接器生命周期、偏移管理、表过滤、标准主题命名与初始快照。部署于 Kafka Connect 环境，要求 Docker 运行集成测试。快照须遵守 tidb_gc_life_time，增量快照与 DDL 解析尚未实现。

  • 消费 TiCDC changefeed 在 protocol=debezium 模式下写入的 Kafka 消息，提供连接器生命周期、偏移存储、表过滤与标准主题命名
  • 支持 initial 快照模式，通过 tidb_snapshot 固定单一 TSO 一致性读取，不加锁，行逐条流式传输，可用 snapshot.fetch.size 批量游标读取
  • 支持 table/column 过滤、消息键指定、列掩码与截断等 Debezium 通用选项，快照与流事件使用同一编码

适用场景（解读层）

  • 已部署 TiCDC changefeed（TiDB v8.0+）且希望以标准 Debezium 消息信封接入 Kafka Connect 的 TiDB 用户
  • 需要初始一致性快照后衔接流式变更、且快照时长可控在 GC 生命周期内的存量数据同步场景
  • 需要通过 table.include/exclude.list 过滤捕获表并按统一主题命名策略路由事件的增量数据管道
