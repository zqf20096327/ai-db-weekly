自托管 Serverless Postgres，项目即 S3 前缀，Rust 实现的 pgwire 列式引擎

综述（解读层）

Basin 用 Rust 编写，前后端分离：前端提供 pgwire v3（含 TLS、COPY、扩展查询、JSONB/UUID/BYTEA 绑定），后端将 Vortex 压缩列式文件写入任意 S3 兼容桶，项目以 S3 前缀而非预置实例存在。面向自行部署、评估多租户成本模型的用户。当前为 pre-alpha，默认 INSERT 先应答后 fsync（≤200ms 丢失窗口），可用 synchronous_commit 开启组提交持久化；部分 SQL 形状（如 INSERT…SELECT）不支持。

  • 单二进制、纯 Rust 异步服务端，README 称每连接内存约 310 KiB（对比其测量的 Postgres 约 8.1 MiB）
  • 项目为 S3 桶前缀，空闲项目仅占用数据字节（README 称约 2 KiB RAM/项目），支持 Iceberg 快照时间旅行与原生向量搜索
  • pgwire v3 前端支持 TLS、COPY、扩展查询，提供 pg_cron/pg_net/pg_trgm/PostGIS 子集的原生 crate 实现

适用场景（解读层）

  • 在自有 S3 兼容对象存储上自托管多租户 Postgres 兼容数据库，为 SaaS 创建大量低成本项目
  • 对列式扫描占主导的分析/读密集负载（JOIN、聚合、大结果流）进行原型验证
  • 评估连接数高、内存受限场景下的 OLTP 部署与成本模型
