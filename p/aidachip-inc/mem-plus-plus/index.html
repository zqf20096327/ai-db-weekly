面向 LLM 代理的追加式组织记忆系统，写入零 LLM 调用，读取时多路检索

综述（解读层）

Mem++ 为处理组织记录（Slack、邮件、会议纪要、工单等）的 LLM 代理提供长期记忆。写入路径逐字保存记录并标注日期与贡献者，不调用语言模型；检索时通过 as-of 日期过滤、词法/向量/实体标签三路加权 RRF 融合，并预留最近记录槽位。依赖 PostgreSQL 16+pgvector，默认使用本地 ONNX MiniLM-384 嵌入，无需 GPU；实体图变体未随本仓库发布。

  • 追加式存储，被取代或冲突的记录仅标记不删除，支持按过去任意日期（occurred_at ≤ θ）回放查询
  • 词法全文检索、pgvector 密集向量和实体标签三路独立排序，经加权 Reciprocal Rank Fusion 融合，另为最新记录保留 3 个槽位
  • 写入零 LLM 调用；可选本地 CPU ONNX MiniLM-384 或 OpenAI text-embedding-3-small 嵌入后端

适用场景（解读层）

  • 从 Slack、邮件、会议纪要与工单中回答问题的组织助理
  • 审计与合规场景下查询某一日期记录的原状
  • 决策溯源与事件复盘，追踪认知随时间的变化
