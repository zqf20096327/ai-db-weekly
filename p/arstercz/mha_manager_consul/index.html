基于 Consul 集群多点健康检查触发 MHA 自动故障切换的工具

综述（解读层）

该项目改写 MHA（v0.5.6 基础）的 masterha_manager，借助 Consul 集群多点检测 MySQL 主库健康状态：checkmysql 部署在各 Consul 节点并写入健康键值，consul-template 监控键变化，当超过半数节点判定异常时触发 masterha_manager_consul 执行 failover，以规避单点网络抖动导致的误切换。依赖 perl-libwww-perl、perl-JSON、perl-Config-IniFiles，采用 MIT/BSD 许可，可与 mha_switch 配合使用。

  • 在各 Consul 服务器上部署 checkmysql，多节点写入 mysql/mysqlxxxx/node-consul 键值（健康为 1，异常为 0）
  • 改写 MHA::HealthCheck::wait_until_unreachable，仅当超过半数 Consul 节点判定异常时 fork 子进程执行 failover，否则退出
  • 支持 --night 选项在 21:00~09:00 忽略 MySQL 状态（服务器宕机时仍上报），并在异常时执行 ssh 端口连接与 ping 检测

适用场景（解读层）

  • MySQL 主库部署 MHA 且需要降低单点网络故障（网卡重启、交换机问题）引起误切换的环境
  • 已运行 Consul 集群并希望复用其多点健康检查与 consul-template 机制的运维体系
  • 主库使用 VIP 的 MySQL 架构（db.cnf 中 host 配置 VIP 地址）
