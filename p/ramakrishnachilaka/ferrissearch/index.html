Rust 编写的分布式搜索引擎，结合 Raft 共识、混合检索与搜索感知 SQL 查询规划

综述（解读层）

FerrisSearch 是一个 pre-1.0 的分布式 Rust 搜索引擎，提供全文检索、向量搜索和 SQL 分析。其机制是将文本匹配、过滤与部分聚合下推到搜索索引附近，跨集群只传输压缩后的部分聚合结果而非全部匹配行；技术栈组合 Tantivy、DataFusion、USearch、openraft 与 tonic，单二进制运行、无 JVM。README 明确声明其尚非 OpenSearch 的生产级替代品，仅支持 query_string 子集，_count?q 与 _msearch 未实现。

  • 支持 local_shards、remote_store、tiered 三种执行模式，可将可变热分片密封为对象存储中的不可变 split 并统一快照读取
  • SQL 中 text_match 等谓词由 Tantivy 求值，符合条件的分片直接从 fast fields 聚合，DataFusion 处理残余关系运算
  • 任意 HTTP 节点均可接收请求，leader-only 元数据变更与分片操作在内部转发，客户端无需发现 Raft leader 或分片 primary

适用场景（解读层）

  • 需要全文检索、向量搜索与 SQL 分析统一服务的实验性部署
  • 以 Rust 工具链构建、希望避免 JVM 依赖的搜索基础设施场景
  • 对分布式查询执行机制（partial aggregation、分片 scatter-gather）进行研究的场景
