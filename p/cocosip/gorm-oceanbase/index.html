GORM 的 OceanBase 方言驱动，经单个 Dialector 支持 MySQL 与 Oracle 两种兼容模式

综述（解读层）

gorm-oceanbase 是基于 go-oceanbase（database/sql 驱动）实现的 GORM 方言，用于连接 OceanBase 的 MySQL 兼容租户和 Oracle 兼容租户，通过 DSN 参数（如 mode=auto 自动探测）或结构化配置选择模式。README 记录了与 OceanBase 4.4.2.2 的实测结果，开发基线为 gorm v1.31.2，早期 GORM 版本的兼容性未声明。限制包括：单 DB 实例仅支持一种模式、NCLOB 与嵌套表列不在支持矩阵内、Oracle 模式不生成 COMMENT ON COLUMN 语句。MIT 许可证发布。

  • 通过 DSN 或配置在单个 Dialector 中选择 MySQL/Oracle 兼容模式，mode=auto 可经临时连接读取 ob_compatibility_mode 探测租户模式
  • 实现 Oracle 模式下的类型映射（Bool→NUMBER(1)、String→VARCHAR2/CLOB 等）、IDENTITY 自增主键回填（INSERT...RETURNING）、OnConflict 到 MERGE INTO 的转换
  • 支持错误翻译（gorm.Config{TranslateError: true}），按模式隔离的代码表将 1062/ORA-00001 等映射为 gorm.ErrDuplicatedKey 等错误

适用场景（解读层）

  • 使用 GORM 访问 OceanBase MySQL 兼容租户的 Go 应用，复用 time.Time 扫描与 gorm.io/driver/mysql v1.6 的字符串/时间默认值语义
  • 使用 GORM 访问 OceanBase Oracle 兼容租户的项目，需要标识符大写折叠、NUMBER 类型映射、序列（OracleSequenceMigrator）或 MERGE upsert
  • 需要在应用配置阶段构造 Dialector 并提前暴露 DSN/配置错误（Open/New 不连接，Initialize 返回错误）的场景
