🧭 简介解读层（AI·证据行可回查）

Text-to-SQL 的 schema 选择器，按调用者权限裁剪送入 LLM 的表清单

综述（解读层）

schemagate 是一个用于 text-to-SQL 场景的 schema 选择工具：先按调用者身份过滤掉无读取权限的表，再用 BM25 与哈希嵌入从剩余表中选出与问题相关的表，只把这些表的 DDL 放入提示词。它提供 CLI、Python API、本地 studio 页面与 MCP/LangChain 集成，支持 Postgres、Oracle、MySQL、SQL Server、SQLite。选择器本身不调用模型，离线运行；依赖 SQLAlchemy，pip 安装即用。README 说明其代价是被需要的表可能被漏选。

  • 按 Principal/角色过滤表目录，无权限的表名不出现在提示词中
  • 表选择由 BM25 加哈希嵌入完成，不调用模型，默认嵌入器离线运行
  • 提供 CLI、本地 studio 页面与 LangChain/LlamaIndex/MCP 集成，支持五种数据库方言

适用场景（解读层）

  • 为 SQL agent 缩减提示词中的 schema 体积
  • 多角色调用同一 text-to-SQL 服务时按身份裁剪可见表
  • 在行级安全之前避免模型针对不可读表生成 SQL
📖 README 首段存档原文 · 程序抽取

Most text-to-SQL prompts carry the whole schema, and on a big database that is most of the prompt, on every question. schemagate sends the model only the tables the question needs: 91.1% fewer schema
