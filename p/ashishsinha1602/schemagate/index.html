🧭 简介解读层（AI·证据行可回查）

文本到SQL的访问控制层，按调用者权限裁剪送入LLM的表结构

综述（解读层）

schemagate 是一个面向文本到SQL（text-to-SQL）应用的 schema 选择工具：在调用方发起提问时，先按其权限（principal 与角色）过滤数据库表目录，仅将被允许且相关的表 DDL 写入提示词，从而避免受限表出现在提示中，也减少提示词 token 消耗。它通过 pip 安装，依赖 SQLAlchemy，可离线运行（BM25 加哈希向量化的选择器不调用模型），支持 Postgres、Oracle、MySQL、SQL Server、SQLite，可集成 LangChain、LlamaIndex、MCP 等代理。需注意：裁剪可能导致问题所需表未被选中，README 自述在部分基准上覆盖率非 100%。

  • 按调用者的 principal 与角色过滤表目录，无权读取的表不出现在提示词中
  • 选择器离线运行（BM25 + 哈希 n-gram 向量化器），不调用模型，无 API 密钥即可使用
  • 支持 Postgres、Oracle、MySQL、SQL Server、SQLite，兼容 LangChain、LlamaIndex、MCP 及任意 SQL 代理

适用场景（解读层）

  • 为大模型 SQL 代理（LangChain/LlamaIndex/MCP）构建按身份过滤的 schema 注入流程
  • 大表数量数据库上减少文本到SQL提示词的 token 消耗
  • 在行级安全（RLS）场景下避免模型对不可读表生成有效但返回空结果的 SQL
📖 README 首段存档原文 · 程序抽取

Most text-to-SQL prompts carry the whole schema, and on a big database that is most of the prompt, on every question. schemagate sends the model only the tables the question needs: 91.1% fewer schema
