Rust 编写的单二进制 HTAP 数据库引擎，以资源契约隔离 OLTP 与 OLAP

综述（解读层）

AngaraBase 是一个用 Rust 实现的 HTAP 数据库引擎，在同一实例、同一份数据上运行行存 OLTP 与列存 SIMD 加速的 OLAP，无需 ETL 管道。它通过 PostgreSQL wire 协议接入标准客户端（psql、JDBC、asyncpg），采用 UNDO-log MVCC 设计，不设 VACUUM。目前处于私有预览阶段，公共基准与安装包计划随 v0.7 开放测试发布；需自行准备 Linux 主机（glibc ≥ 2.28），暂不支持 PL/pgSQL、触发器及 Postgres 第三方扩展。

  • 在同一进程内提供行存 OLTP 与列存 SIMD 加速的 AngaraColumn OLAP 引擎，通过 TableEngine trait 支持可插拔存储引擎，AngaraMemory 含 none/logged/snapshotted 三种持久化层级
  • 按工作负载类别实施八项命名资源边界（内存、UNDO、写集、连接数等），越界时返回确定性 SQLSTATE 错误并输出对应 Prometheus 指标
  • 实现 ARIES 恢复（Analysis→Redo→Undo 含 CLR）、UNDO-log MVCC，支持 LISTEN/NOTIFY，内置 SCRAM 认证、60+ 系统视图与 USDT 探针

适用场景（解读层）

  • 需在同实例内对实时交易数据运行聚合分析、希望避免搭建 ETL 管道（Kafka/Debezium/ClickHouse 组合）的团队
  • 对延迟抖动敏感的业务场景，如计费、欺诈检测等需要在同一实例上并行处理高写入事务与模式检测聚合
  • 使用 psql/JDBC/libpq/pgx/asyncpg 等标准 Postgres 客户端、且可自行运维 Linux x86_64/aarch64 主机的自托管部署
