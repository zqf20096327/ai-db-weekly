基于 AWS CDK、Lambda 与 Knex.js 将 RDS 数据库 schema 变更集成进 CI/CD 流水线的示例项目

综述（解读层）

该项目提供一套 AWS CDK 代码，构建跨账户 CI/CD 流水线（CodeCommit 触发、CodePipeline 两阶段部署至开发与生产账户），资源部署后由 CodeBuild 触发 Lambda 执行 Knex.js 迁移文件以变更 Aurora PostgreSQL 数据库 schema。示例部署的是 Aurora PostgreSQL Serverless，概念可推广至其他受支持的 RDS 引擎；清理时需手动删除流水线创建的 CloudFormation 栈。

  • 使用 CDK Pipelines 构建双阶段（开发/生产）跨账户流水线，源代码来自 CodeCommit 并在推送时触发
  • 通过 AWS Lambda 函数执行基于时间戳命名的 Knex.js 迁移文件，在资源部署后自动应用 schema 变更
  • 部署 Bastion Host，支持经 AWS Session Manager 端口转发从本地连接私有 VPC 内的数据库

适用场景（解读层）

  • 需要将 RDS/Aurora 数据库 schema 变更纳入应用 CI/CD 流程的团队
  • 使用 AWS 双账户（开发/生产）结构进行部署的环境
  • 需要从本地机器访问私有 VPC 中 PostgreSQL 数据库进行调试的场景
