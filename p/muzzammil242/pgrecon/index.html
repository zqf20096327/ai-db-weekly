🧭 简介解读层（AI·证据行可回查）

离线采集 Oracle 字典生成 SQLite 清单，用确定性规则引擎做迁移评估并输出可应用的 PostgreSQL DDL。

综述（解读层）

pgrecon 从离线 dump 评估 Oracle 到 PostgreSQL 的迁移并转换 schema。流程为：DBA 用只读账号运行可审查的 SQL*Plus 提取脚本，pgrecon 加载 dump 生成本地 SQLite 清单，再对清单跑带稳定 ID 的确定性规则（当前 80 条），按严重度报告发现；转换器对可证明的构造生成 DDL，对不能转换的按名拒绝。分析端需 Python 3.11+，全程不连接数据库，仓库自带样例 dump 可直接试用。

  • 离线运行：提取脚本仅 SELECT 字典视图，工具不连接数据库，只处理文件边界
  • 80 条规则带稳定 ID 和 fixture 测试，PL/SQL 经完整语法树解析，发现不来自注释或字符串字面量
  • 转换器输出可应用的 PostgreSQL DDL，无法转换的对象以命名 residue 行列出；CI 每次提交在 PostgreSQL 16/17/18 上实测应用样例转换

适用场景（解读层）

  • 迁移前评估：找出包级状态、自治事务、LONG 列、间隔分区、database link 等决定迁移成本的对象
  • DBA 友好的安全采集：提取脚本可先审阅，用只读账号在源库运行
  • 生成 schema 结构、视图、物化视图、触发器、授权、注释的 PostgreSQL DDL 转换初稿
