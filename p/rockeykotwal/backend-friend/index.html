🧭 简介解读层（AI·证据行可回查）

基于 Meta AI 模型的 ORM 级数据库查询分析工具，检测 N+1 等问题并返回修复代码

综述（解读层）

Backend Friend 是一个 AI 数据库查询分析器，扫描代码库中的 ORM 查询块，检测 N+1、缺失索引、过度取数等问题，并返回修复后的 ORM 代码与迁移脚本，面向使用各语言 ORM 的后端工程师。它工作在 ORM 层而非原始 SQL 层，支持 8 种语言、30 余个 ORM 及 NoSQL 驱动。隐私方面，默认模型承诺代码不用于训练，但 Economy 模式（muse-spark-1.3-contributor）需用户显式勾选同意，Meta 可能使用提交的代码训练模型。MIT 许可。

  • 支持 8 种语言（Node.js、Python、Go、Java/Kotlin、Ruby、PHP、C#、Rust）的 30 余个 ORM 及 SQL/NoSQL 驱动，包括 Prisma、SQLAlchemy、GORM、Hibernate、Entity Framework Core 等
  • 提供单查询分析、GitHub 仓库代理式扫描、本地文件夹扫描三种方式，输出按严重程度排序的问题列表、生成的 SQL、修复代码及索引迁移脚本
  • 使用四个 Meta 模型（muse-spark-1.3、muse-wonder-1.0、muse-image-1.0、muse-voice-transcribe-1.0），文本模型共享 1M token 上下文窗口；内置 50kb 请求上限与按 IP 的 15 分钟滚动窗口限流

适用场景（解读层）

  • 在 ORM 代码编写阶段分析查询，获取问题严重程度、生成的 SQL 及修复后的 ORM 代码与索引迁移脚本
  • 提交 GitHub 仓库地址或上传本地文件夹，对整个代码库中的 ORM 查询进行批量扫描并按严重程度排序
  • 对敏感代码有训练顾虑的团队使用默认 Balanced/Deep 模式（代码不用于训练），或在显式同意后使用成本更低的 Economy 开源权重模型
