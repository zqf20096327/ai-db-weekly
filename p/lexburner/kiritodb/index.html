Java 实现的 KV 存储引擎，按 key 高位分区将随机写转为局部顺序写

综述（解读层）

lexburner/kiritoDB 是作者参加 PolarDB 性能大赛时用 Java 实现的 KV 存储引擎，支持 write、read、range 接口。它将数据按 key 高 10 位哈希为 1024 个分区，写入时顺序追加落盘，恢复阶段用 64 线程并发重建内存索引，Range 采用生产者-消费者模型读盘缓存。实现细节以赛事评测场景为约束，面向参赛与存储引擎学习场景。

  • 提供 write、read、range 接口，key 固定 8B、value 固定 4KB
  • 按 key 高位哈希实现 1024 个数据分区，随机写转为分区顺序追加写
  • 使用 mmap 写索引缓冲、JNA 封装 Direct IO，并提供 JVM 参数调优与线程绑核配置

适用场景（解读层）

  • 参加 PolarDB 等存储性能竞赛的 Java 实现参考
  • 学习 Java 编写存储引擎的 IO、索引恢复与 JVM 调优实践
  • 需要 kill -9 后数据可恢复的键值读写与范围遍历场景
