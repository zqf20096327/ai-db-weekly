🧭 简介解读层（AI·证据行可回查）

将 OpenTelemetry 追踪与日志转为错误故事的自托管 Rust 可观测性工具

综述（解读层）

Tayga 用 Rust 编写，读取标准 OTLP 追踪与日志，经 Redpanda 流式处理、ClickHouse 存储，为每个失败或慢请求生成包含根因 span、请求路径、关键路径与基线对比的错误故事，并将同类问题折叠为故事组；同时对日志挖掘模板并在新增、激增或静默时告警。适合需要自托管、基于确定性规则（非 LLM）做根因分析、并自带服务地图与日志告警的团队。注意其不采集 OTel 指标，慢请求阈值为 max(p99×1.5, p99+100ms)，采用 AGPL-3.0 许可。

  • 接收 OTLP gRPC（4317）与 HTTP（4318），按 trace id 聚合并以固定规则生成根因与关键路径，不使用 LLM
  • 在摄入阶段用 Drain 挖掘日志模板，支持新增、速率激增与静默三类告警，投递至 webhook 和 Slack
  • 提供 Docker Compose 一行安装、Kubernetes Helm chart，内置服务地图、trace 浏览器与管道自身健康指标

适用场景（解读层）

  • 需要为失败或慢请求自动生成根因说明、而不用人工翻查大量 trace 的微服务环境
  • 已接入 OpenTelemetry Collector、希望自托管并结合 ClickHouse 存储与日志模板告警的团队
  • 需要在 Kubernetes 上评估或部署，并通过服务地图与服务基线观察速率、错误率与 p99 的场景
