TiDB 集群部署与测试记录：6 节点部署 Java API 并做负载与故障转移测试

综述（解读层）

该仓库记录了一次课程期末项目中 TiDB 集群的部署与测试过程：3 个 PD 节点、3 个 TiKV 节点运行于 CentOS 8，部署一个 Java/Spring 会计 API 作为上层应用，并包含 sysbench 数据库压测、Web 并发测试与 TiKV 故障转移演示。作者同时记录了部署限制：512MB 内存下 TiKV 被 OOM 杀死，需加 swap 才能完成压测。适合作为个人学习性质的 TiDB 多节点部署实践参考。

  • 包含 3 PD + 3 TiKV 的六节点部署拓扑，含各节点 IP、内存与运行服务清单
  • 应用层为一个 Java Spring + Hibernate 的 12 端点会计 API（Pendapatan/Pengeluaran 收支记录）
  • 使用 sysbench oltp_read_write（10 万行、300 秒）分别在 3/2/1 个 PD 下压测，并记录 1 PD 时 PD server timeout、2 PD 略快于 3 PD 的实测结果

适用场景（解读层）

  • 参考在低内存（8GB 总内存）环境下搭建 TiDB 多节点集群并处理 TiKV OOM 问题
  • 参考 Java Spring + Hibernate 应用连接 TiDB 时的连接串与 DDL 语法调整（如不支持建表后添加主键/auto_increment）
  • 了解 TiKV 单节点下线与恢复的故障转移验证方法
