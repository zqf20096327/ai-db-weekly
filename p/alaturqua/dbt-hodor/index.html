🧭 简介解读层（AI·证据行可回查）

在 dbt 内逐节点判定复用或重建的自托管状态工具

综述（解读层）

dbt-hodor 运行于 dbt 内部，对每个选中节点哈希其编译 SQL 与配置，并检查上游表的数据版本，逻辑与上游数据均未变化时返回 reuse，否则返回 build 并附带原因码。状态存于 Delta、Trino、Postgres 或本地 DuckDB，不需 dbt 平台账号。默认为 shadow 模式：只记录决策、全部构建。README 明确其处于早期开发阶段，尚未在大规模生产项目中运行。

  • 用 sqlglot 按目标方言归一化 SQL 后哈希，大小写、引号、注释和别名不视为变更；无代码变化时直接复用上次的哈希分析
  • 上游数据版本分别来自 Delta 提交历史（忽略 OPTIMIZE/VACUUM）、Iceberg 快照、Snowflake SYSTEM$LAST_CHANGE_COMMIT_TIME 或 DuckDB 内容指纹
  • 失败即构建：判定出错、存储不可读或上游不可追踪时节点按普通 dbt 方式构建，不会中断运行

适用场景（解读层）

  • 在 Databricks、Trino、Snowflake 或 DuckDB 上的调度化 dbt run/build/test/seed/snapshot 中跳过未变化节点
  • 通过读取与 dbt State 相同的 state: 配置块，在不使用 dbt 平台账号的项目里做基于状态的增量构建
  • 以默认 shadow 模式先运行一个调度周期、比对决策记录后再启用复用
