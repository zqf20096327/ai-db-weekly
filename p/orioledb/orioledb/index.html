基于表访问方法框架的 PostgreSQL 云原生存储引擎扩展

综述（解读层）

OrioleDB 以 PostgreSQL 扩展形式实现的新存储引擎，通过表访问方法接口挂接，需配合 .pgtags 指定 commit 的打过补丁的 PostgreSQL 源码构建，并设置 shared_preload_libraries 后经 CREATE EXTENSION 启用，建表时用 USING orioledb。提供 64 位事务标识、undo 日志、行级 WAL、copy-on-write 检查点等机制。当前为公测状态，官方不建议用于生产。

  • 实现 undo 日志、页合并与默认 64 位事务标识，表无需专用 VACUUM 垃圾回收
  • 实现行级 WAL 日志，支持并行回放，面向基于 raft 共识的复制架构
  • 内存页通过直接链接关联存储页，页读取不涉及原子操作；支持 amd64 与 arm64v8 的 Alpine/Ubuntu Docker 镜像

适用场景（解读层）

  • 在 PostgreSQL 16/17/18 上以 USING orioledb 表访问方法创建 OrioleDB 表进行实验与测试
  • 通过 Docker 镜像（需 locale 设为 C/POSIX/ICU）快速运行带 OrioleDB 引擎的 PostgreSQL 实例
  • 面向多核服务器、SSD/NVRAM 存储环境进行基准测试与评估
