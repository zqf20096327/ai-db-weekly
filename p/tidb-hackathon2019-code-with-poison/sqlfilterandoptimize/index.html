基于 TiDB 的 SQL 过滤与优化工具，源自 TiDB Hackathon 2019 项目

综述（解读层）

该项目为 TiDB Hackathon 2019 的参赛作品，作者在手动迁移 800+ 存量 MySQL SQL 到 TiDB 的过程中，总结了导致集群 CPU 和内存消耗升高的问题，如 where 条件使用内置函数、类型不匹配、IN 语法导致索引失效等。项目实现对仅使用 TableScan 的 SQL 进行过滤，并提供指定 IndexScan、提示添加或强制索引等优化手段。适合在 MySQL 向 TiDB 迁移场景中排查 SQL 质量问题的用户。

  • 提供 SQL 过滤能力：识别仅使用 TableScan 的语句，以及 Selection/TableReader 行数超过 1000 万的语句
  • 提供优化能力：指定 where 条件字段使用 IndexScan，生成添加索引与强制使用索引的提示
  • 包含 8 个优化案例，覆盖存在索引但未使用等迁移常见问题

适用场景（解读层）

  • 从 MySQL 迁移存量 SQL 到 TiDB 时排查索引失效问题
  • 定位引发集群 CPU 与内存资源紧张的 SQL 语句
  • 处理 varchar 字段大小写敏感差异、bit 类型查询等 MySQL 与 TiDB 行为差异
