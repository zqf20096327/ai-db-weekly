🧭 简介解读层（AI·证据行可回查）

基于 hook 自动记录编码代理会话并支持检索注入的本地长期记忆系统

综述（解读层）

Kizami 是一个运行于本地的长期记忆系统，通过 SessionEnd/SessionStart/UserPromptSubmit 等 hook 自动记录 Claude Code、Codex、Kimi Code 的会话，并在新会话中检索、注入历史记忆。数据以 JSONL 正本加 SQLite 缓存的二层结构存储，检索默认使用 FTS5 trigram 与 BM25 加时间衰减，可选 hybrid 模式接入 Ruri v3 向量检索。core 模式运行时依赖仅 better-sqlite3，分块采用规则方式，不调用 LLM；需 Node.js 24.15.0 以上与 pnpm 11 以上，通过克隆仓库构建后 npm link 安装。

  • 支持 Claude Code、Codex、Kimi Code 三种运行时的会话自动保存与记忆注入，通过 kizami setup 一条命令完成数据库初始化与 hook 配置
  • 采用 append-only JSONL 正本加可重建 SQLite 缓存的存储结构，包含事务帧与 payload 校验，并内置删除超过 90 天旧数据、控制数据库体积上限的自动维护
  • 提供 kizami search/show/resume/edit/delete/resolutions 等 CLI 命令，可检索、查看、恢复会话，记录同一会话内失败命令后续成功运行的验证记录，并经 kizami-recall 技能响应唤起旧对话的请求

适用场景（解读层）

  • 希望在没有外部 API 调用的情况下，让 Claude Code 会话在结束后被本地保存，并在后续会话开始或发送提示时自动引入相关历史讨论
  • 需要检索或重读过往编码会话，包括已被 Claude Code 按清理期限删除的对话（前提是此前已有 kizami 保管副本），并使用 kizami resume 在原工作目录继续会话
  • 想按会话、日期或单个分块编辑、删除、导出本地记忆数据，或用 --recall-only 配置只保留日志保存与手动检索、关闭自动注入
