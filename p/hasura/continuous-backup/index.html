基于 Postgres 归档与 wal-e 的 Kubernetes 连续备份与恢复脚本集

综述（解读层）

该项目通过 Postgres 连续归档机制，借助 wal-e 将 WAL 备份推送到用户自有的云存储（当前仅支持 S3），项目本身不保存备份。面向 Hasura 项目用户，提供 configure_backup.sh、stop_backup.sh 和 recovery.sh 三个脚本完成备份配置、停止与按时间点恢复。恢复后需手动同步旧项目的 postgres 与 auth 密码；stop_backup.sh 不保证正确回滚部署。

  • 通过 Postgres archive 命令与 wal-e 实现连续归档，支持热备份和 PITR
  • 备份写入用户自配置的 S3 存储桶，项目方不保留备份数据
  • 以 Kubernetes 资源文件和 shell 脚本方式部署，恢复状态可通过 postgres pod 日志或 recovery.done 文件查看

适用场景（解读层）

  • 为运行在 Hasura 项目集群上的 Postgres 数据库配置连续备份
  • 需要按时间点恢复（PITR）数据库时执行恢复流程
  • 需要停止已有备份任务或从备份恢复到新 Hasura 项目时使用
📖 README 首段存档原文 · 程序抽取

We use the continuous archiving method of Postgres to backup your Postgres database. This gives the flexibility of hot backups and Point-in-time recovery (PITR).
