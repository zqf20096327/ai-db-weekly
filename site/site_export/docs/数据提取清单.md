# 数据提取清单（数据库开源生态观察 · 四件套）

> 三层数据模型：**L1 采集字段**（GitHub API 原始字段）→ **L2 推导字段**（管道计算）→ **L3 产品数据集**（四个产品各自吃的数据文件）。
> 状态标注：✅ 已在采 / 🔧 已采未用（接回即可）/ ➕ 需新增 / 🧮 纯计算（零采集）。

## L1 · 采集字段（每日快照，per repo）

| 字段 | 来源 | 状态 | 用途 |
|---|---|---|---|
| `full_name` / `html_url` | repo 元数据 | ✅ | 主键 key = owner/repo，全链路去重 |
| `stargazers_count` | repo | ✅ | 榜单、sparkline、增长 |
| `forks_count` / `open_issues_count` / `watchers_count` | repo | ✅ | 健康度辅助 |
| `license.spdx_id` | repo | ✅ | 合规分档 |
| `language` | repo | ✅ | 语言分布 |
| `created_at` / `pushed_at` / `archived` | repo | ✅ | 新锐判定、停更预警 |
| `topics[]` / `description` / `homepage` | repo | ✅ | 分类、适用库推断 |
| `commit_count_7d` | participation / search commits | ✅（头部 4000 项） | 真实活跃度 |
| `source`（topic/org/whitelist/new） | 采集来源 | ✅ | 官方出品判定 |
| `releases[]`（tag / name / published_at / body / prerelease） | `/repos/{o}/{r}/releases` | 🔧 采集器已有、新 SOP 移除 | 版本速递、安全修复关键词 |
| `security_advisories[]`（ghsa_id / summary / published_at / severity） | `/repos/{o}/{r}/security-advisories` | ➕ 仅上榜项目 | 安全修复汇总（项目自述口径） |
| `contributors_count` | `/repos/{o}/{r}/contributors?per_page=1` 看 header | ➕ 仅上榜项目 | bus factor/贡献者集中度 |
| `owner_type` + `owner_login` | repo.owner | ➕ | 官方组织徽章（org 与库名同名或白名单） |

## L2 · 推导字段（管道计算，不新增采集）

| 字段 | 计算规则 | 状态 |
|---|---|---|
| `growth` / `growth_type` | Δstars vs 7 天前基准快照；与 commit 活跃分列两种单位 | 🧮 |
| `weeks_in_pool` / `growth_streak` | 周锚点（每周最后一个快照）出现次数 / 连续上涨周数，**跳过无数据锚点**，zip 归档一并读入 | 🧮（zip 并入需改一行） |
| `spark[]` | 逐快照 star 序列（含 zip 日） | 🧮 |
| `health.stale_days` | 今天 − pushed_at；≥30 预警、≥90 标红、archived 单标 | 🧮 |
| `license_tier` | MIT/Apache/BSD→绿；AGPL/LGPL→黄（法务过）；SSPL/BSL/自定义→红；规则表公开挂页面 | 🧮 |
| `cat`（任务分类） | 现有 8 分类关键词 + 兜底增强规则（backup/dump→备份，proxy/pool→连接代理等，已验证「其他」70%→51%）→ **批量 AI 分类 805 个 star≥300 项目（一次性）**，新项目增量 | 🔧+➕ |
| `dbs[]`（适用库，规范化） | desc+topics+推断串 对库名做子串匹配，清洗「（本体）」噪声；国产库覆盖靠 README 复核扩展到 star≥300 项目 | 🔧 |
| `personas` / `ai` | 主类 use/ops/build（由 cat+描述映射）+ AI 横切（去 AI 能力是否成立） | ➕ 采集端 AI 输出，规则兜底 |
| `official` | source=org/whitelist 且 owner 与库名同名（或白名单） | 🧮 |
| `is_newface` | 新入池（基准快照无）且未在近期周报出现 | 🧮 |
| `threshold_pass` | star≥50 或官方出品（门槛规则，透明展示未过门槛项） | 🧮 |

## L3 · 产品数据集（四个产品各自的数据文件）

**1. `weekly-{N}.json`（周报 v4 骨架）**：`kpi`（有增长/新入池/让位数）+ `hooks[3]`（人工看点）+ `board_secs{国外,国产,AI}[3]`（轮换后定榜，行内含 L2 全字段 + AI 解读缓存）+ `focus`（三维解读 + 爆发豁免备注）+ `newfaces[]`（触发式）+ `topboard[5]` + `rotated_out[]`（透明让位名单）。

**2. `monthly-{YYYY-MM}.json`（月度速报）**：`top_gain[10]`（月窗 Star 净增）+ `streaks[]`（连涨≥3 周）+ `orgs[]`（月活跃/活跃率/新开，首扫标注）+ `month_new_top[]` + 窗口口径（基准快照对）。

**3. `archive-{db}.json`（数据库档案页）**：`total/cats/top[40]/licenses/langs/week_up`（star≥300、按任务分组、每组前 N）——本次已验证：PG 504 / MySQL 373 / SQLServer 111 / Oracle 94 / ClickHouse 88 / MariaDB 86 / TiDB 33 / OceanBase 5（国产薄，随标注补齐）。

**4. `map.json`（工具地图）**：`matrix{db×cat}` 计数 + `cells{db×cat}[fn]` 明细——本次已验证 42 个 ≥2 项目的有效格。

## 质量前置（做地图/档案前必须完成的两次性投入）

1. **批量 AI 分类**：805 个 star≥300 项目跑一次 personas + 任务分类（prompt 用已定判定顺序 + 灰地带表 + 已标样本），此后新项目增量分类；
2. **国产库适用标注**：README 范围复核从「上榜项目」扩展到「star≥300 项目」，补 OceanBase/openGauss 等库的项目归集。
